# Godot 4 `.tres` Resource Authoring Guide

This guide is a self-contained reference for generating Godot 4.7 text
resource files (`.tres`) without opening the Godot editor. It is intended for
AI systems and tools that need to emit resource files with the structure and
value shapes expected by Godot's text resource loader.

The `.tres` format is a text serialization of one Godot `Resource`. It is not
JSON, YAML, or a general-purpose data format. The resource class, property
names, property types, resource references, and custom scripts must all be
valid for the target Godot project.

Read [`shared_concepts.md`](shared_concepts.md) for the
shared rules on project-specific facts, typed values, resource sharing,
identifiers, dependencies, lifetime, and validation. This guide retains the
`.tres` grammar and resource-specific serialization rules.

## 1. What `.tres` represents

Use `.tres` for a human-readable, version-control-friendly resource saved on
disk. A resource is usually a data object such as:

- `Resource` or a custom script extending `Resource`;
- `Material`, `ShaderMaterial`, `StandardMaterial3D`;
- `Gradient`, `Curve`, `Curve2D`, or `Curve3D`;
- `Animation`, `AnimationLibrary`, or `SpriteFrames`;
- `Mesh`, `ArrayMesh`, `Shape2D`, `Shape3D`, or `NavigationMesh`;
- `Theme`, `StyleBox`, `LabelSettings`, or `Font`;
- `Environment`, `Sky`, `AudioBusLayout`, or another engine resource.

Resources inherit reference-counted lifetime behavior. The shared concepts
guide defines the general sharing and mutation rule; `.tres` additionally
supports `resource_local_to_scene` when a resource must be duplicated
separately for each instantiated scene.

The binary counterpart is `.res`. `.tres` is preferable for hand authoring and
review because it is text; `.res` is generally smaller/faster and should be
generated by Godot or `ResourceSaver` rather than hand-written.

Do not use `.tres` for scene trees. Use `.tscn` for nodes, child hierarchy,
scene instances, and signal connections.

## 2. Compatibility rules

Use these rules when generating a Godot 4.7 `.tres` file:

1. Start with a `[gd_resource ...]` header.
2. Use `format=3` for Godot 4.
3. Put external resources before sub-resources.
4. Put sub-resources before the resource or sub-resource that references them.
5. Put the main resource properties under one final `[resource]` heading.
6. Use `ExtResource("id")` for external resources and
   `SubResource("id")` for embedded resources.
7. Keep external and internal resource IDs exact and unique within their own
   namespaces.
8. Serialize values using Godot Variant text syntax, not JSON syntax.
9. Use only properties that exist on the declared resource class or its
   inheritance chain.
10. Omit default-valued properties unless their explicit presence is required.
    Godot commonly removes default-valued properties when saving.
11. Use a real UID only when it was generated for the intended project/resource.
12. Preserve exact generated structures for complex packed data such as meshes,
    images, tile sets, and imported resources.

The format can parse successfully while still failing semantic loading. A
valid file also needs a real resource class, valid properties, compatible
Variant values, resolvable external paths, and compatible custom scripts.

## 3. Minimal valid resources

The smallest useful built-in resource is:

```text
[gd_resource type="Resource" format=3]

[resource]
```

A typed resource can declare its engine class:

```text
[gd_resource type="StandardMaterial3D" format=3]

[resource]
albedo_color = Color(1, 1, 1, 1)
roughness = 0.5
```

The type in the header controls which properties are valid. Do not declare
`type="Resource"` and then assume properties from an unrelated subclass are
available.

A generic script-backed custom resource can declare `type="Resource"` and
attach a script:

```text
[gd_resource type="Resource" format=3]

[ext_resource type="Script" path="res://data/bot_stats.gd" id="1_script"]

[resource]
script = ExtResource("1_script")
health = 100
speed = 4.0
```

The script must extend `Resource` or a compatible `Resource` subclass. Its
exported properties must exist and their serialized values must match the
declared property types. Named script classes may produce a more specific
`type` and a `script_class` header attribute. For a script-defined resource,
prefer the exact header emitted by the target Godot version instead of
guessing whether it should use `Resource` or the global class name.

## 4. File-level grammar

A text resource consists of headings followed by property assignments:

```text
[<resource_type> key1=value1 key2=value2 ...]
property_name = value
another/property_name = value
```

The headings relevant to `.tres` are:

- `gd_resource`: the file descriptor; it must be first;
- `ext_resource`: a reference to a resource stored outside the file;
- `sub_resource`: a resource embedded inside the file;
- `resource`: the main resource represented by the file.

Example:

```text
[gd_resource type="GradientTexture2D" format=3]

[sub_resource type="Gradient" id="Gradient_gradient"]
colors = PackedColorArray(1, 0, 0, 1, 0, 0, 1, 1)
offsets = PackedFloat32Array(0, 1)

[resource]
gradient = SubResource("Gradient_gradient")
width = 256
height = 256
```

Properties continue until the next heading. A property name can contain `/`
when the resource class exposes a serialized property path:

```text
some_property/sub_property = 1
```

Do not invent slash-separated names. They must match the serialized property
names produced by the target Godot class or editor.

Single-line comments begin with `;`:

```text
[gd_resource type="Resource" format=3] ; Comment accepted while loading
```

Comments are discarded when Godot saves the file. Whitespace is not
significant outside strings and is normally normalized when the editor saves.
Do not rely on comments or whitespace as resource metadata.

## 5. Header and format version

The normal Godot 4 header is:

```text
[gd_resource type="Resource" format=3]
```

Header attributes:

- `type`: the resource class to instantiate;
- `format=3`: the Godot 4 text resource format;
- `uid="uid://..."`: the resource's string-based unique identifier;
- `load_steps=<integer>`: legacy metadata found in files saved before Godot
  4.6; do not add it to new files;
- `script_class="..."`: optional metadata that may be emitted for some
  script-defined resource classes; reproduce it only when the target Godot
  version generates it for the resource.

The `type` is a class name, not a file extension and not a local resource ID.
Examples include `Resource`, `Gradient`, `ShaderMaterial`, `Animation`, and
`ArrayMesh`.

Godot 3 uses `format=2` and has different resource, UID, mesh, skeleton, and
animation serialization. Do not mix Godot 3 and Godot 4 conventions.

## 6. Resource UIDs

The header UID identifies the resource independently of its filesystem path:

```text
[gd_resource type="Gradient" format=3 uid="uid://c4mplegradient0001"]
```

A trustworthy UID lets Godot and scripts continue resolving the resource when
the file is moved:

```gdscript
var gradient: Gradient = load("uid://REPLACE_WITH_VALID_UID")
```

Rules:

- A UID must be generated for the intended project/resource.
- Never copy an example UID into a real project.
- Never use a filesystem path as a UID.
- Omit the UID if no trustworthy generator is available.
- A header UID is different from the local `id` used by `ExtResource()` and
  `SubResource()`.

External resources can also have UIDs. Their UID maps the resource to its
filesystem location, while the local `id` is used only inside this file.

## 7. External resources

An external resource is stored in another file. Its heading normally contains:

- `type`: the referenced resource class;
- `uid`: the resource UID, when available;
- `path`: the resource path;
- `id`: the local reference ID used in this `.tres`.

Example:

```text
[ext_resource type="Texture2D" uid="uid://ccbm14ebjmpy1" path="res://art/gradient.png" id="1_texture"]
[ext_resource type="Shader" path="res://shaders/water.gdshader" id="2_shader"]
[ext_resource type="Script" path="res://data/item_data.gd" id="3_script"]
```

Reference them with:

```text
albedo_texture = ExtResource("1_texture")
shader = ExtResource("2_shader")
script = ExtResource("3_script")
```

Rules:

- The local `id` must match the `ExtResource("...")` argument exactly.
- External IDs must be unique among external resources in this file.
- The same text ID may also be used by a sub-resource because the namespaces
  are separate, although distinct IDs are clearer for humans.
- Prefer project-absolute `res://` paths.
- Relative paths can be valid, but are more ambiguous and should match
  Godot-generated output exactly when used.
- The declared `type` must match the resource that the path loads.
- The path must exist and contain a loadable resource when the file is loaded.
- Do not pass a filesystem path to `ExtResource()`. Its argument is the local
  resource ID, not the path or UID.

An external resource is shared by every user that loads the same resource path.
Use a sub-resource or `resource_local_to_scene` when independent mutable data
is required.

## 8. Internal sub-resources

A sub-resource is embedded in the `.tres` file:

```text
[sub_resource type="Gradient" id="Gradient_gradient"]
colors = PackedColorArray(1, 0, 0, 1, 0, 0, 1, 1)
offsets = PackedFloat32Array(0, 1)
```

Reference it with:

```text
gradient = SubResource("Gradient_gradient")
```

Rules:

- Every sub-resource ID must be unique among sub-resources.
- The ID is an arbitrary local string, but references are case-sensitive.
- A sub-resource has no filesystem `path` in its heading.
- A sub-resource may reference external resources.
- A sub-resource may reference another sub-resource.
- If sub-resource A references sub-resource B, define B before A.
- A sub-resource is owned by the containing resource and is not independently
  loadable by its local ID.
- A sub-resource is normally saved as part of the parent file and may be
  duplicated when the parent resource is duplicated.

Example dependency chain:

```text
[sub_resource type="StandardMaterial3D" id="StandardMaterial3D_material"]
albedo_color = Color(0.2, 0.6, 1, 1)

[sub_resource type="BoxMesh" id="BoxMesh_mesh"]
size = Vector3(2, 1, 2)
material = SubResource("StandardMaterial3D_material")

[resource]
mesh = SubResource("BoxMesh_mesh")
```

The material must appear before the mesh, and the mesh must appear before the
main resource references it.

## 9. The main `[resource]` section

The `[resource]` heading identifies the resource saved by the file:

```text
[gd_resource type="Gradient" format=3]

[resource]
colors = PackedColorArray(1, 0, 0, 1, 0, 0, 1, 1)
offsets = PackedFloat32Array(0, 1)
```

There is normally exactly one `[resource]` section. Its properties belong to
the type declared in `[gd_resource]`.

Common inherited `Resource` properties:

| Property | Meaning |
| --- | --- |
| `resource_name` | Optional human-readable name shown by the Inspector. It does not change the resource class or path. |
| `resource_local_to_scene` | If `true`, duplicate this resource for each scene instance that uses it. This prevents runtime changes in one scene instance from affecting other instances. |
| `resource_path` | Engine-managed path. Do not normally hand-write it in a `.tres`; the saved file path supplies it. |
| `resource_scene_unique_id` | Editor/scene-local identity metadata. Omit it unless reproducing exact generated output requires it. |

Example:

```text
[gd_resource type="Resource" format=3]

[resource]
resource_name = "Enemy defaults"
resource_local_to_scene = true
```

`resource_local_to_scene` affects resources duplicated during
`PackedScene.instantiate()`. Changing it at runtime does not retroactively
change resources that were already duplicated.

Do not serialize `resource_path` merely to make a resource look complete. The
loader and resource cache determine the path from the file being loaded.

## 10. Custom Resource scripts

Custom resources are scripts that extend `Resource` or a compatible subclass:

```gdscript
class_name ItemData
extends Resource

@export var display_name: String = ""
@export var value: int = 0
@export var icon: Texture2D
```

A matching `.tres` can be:

```text
[gd_resource type="Resource" format=3]

[ext_resource type="Script" path="res://data/item_data.gd" id="1_script"]
[ext_resource type="Texture2D" path="res://art/item_icon.png" id="2_icon"]

[resource]
script = ExtResource("1_script")
display_name = "Health Potion"
value = 25
icon = ExtResource("2_icon")
```

The script path is serialized as an external `Script` resource. When the file
loads, Godot checks that the script is compatible with the declared resource
type and then restores its exported properties.

Rules for custom resources:

- The script must extend `Resource` or a compatible subclass.
- Every serialized custom property must still exist when the file is loaded.
- Property names are exact and case-sensitive.
- Property values must match the script's exported types.
- Use `class_name` when the resource should appear in the editor's creation
  dialog as a global resource type.
- Give constructor parameters defaults when the resource must be created and
  edited reliably through the Inspector.
- Do not use an inner GDScript class as the serialized custom resource type.
  The script path must resolve to a compatible top-level resource script.
- Renaming or moving the script can make existing `.tres` files fail to load
  unless the serialized script path is updated.

Resource scripts can define methods, signals, setters, getters, constants,
and nested resources. Those runtime features are not represented by new
arbitrary `.tres` headings; only serializable properties are written.

## 11. Variant value serialization

Property values use Godot's text Variant syntax. Common forms include:

```text
enabled = true
count = 3
ratio = 0.5
negative = -2
label = "Hello"
color = Color(1, 0.5, 0.25, 1)
position = Vector2(10, 20)
position_3d = Vector3(1, 2, 3)
rotation = Quaternion(0, 0, 0, 1)
transform = Transform3D(1, 0, 0, 0, 1, 0, 0, 0, 1, 1, 2, 3)
path = NodePath("Player")
items = ["one", "two"]
settings = {"mode": 1, "enabled": true}
names = PackedStringArray("A", "B")
values = PackedFloat32Array(0, 1, 2)
resource = ExtResource("1_resource")
embedded = SubResource("Gradient_gradient")
```

Important distinctions:

- `Vector2`, `Vector3`, and `Vector4` have different component counts and
  cannot be substituted for one another.
- Integer vector types such as `Vector2i` are distinct from float vectors.
- `Quaternion` is a rotation representation, not three Euler angles.
- `Transform2D` and `Transform3D` have different serialized component layouts.
- `NodePath("...")` is not the same as the string `"..."`.
- `StringName("...")` and `NodePath("...")` are distinct Variant types.
- `PackedFloat32Array(...)` is not a normal `Array`.
- A resource reference must use `ExtResource(...)` or `SubResource(...)`.
- A dictionary is not a JSON object when its values require typed Godot
  constructors or resource references.
- `null` is a null Variant and is only valid where the property accepts null.
- `RID`, `Callable`, live `Object` instances, and other runtime-only values
  should not be invented as serialized property values.

Strings use quoted text and Godot escape sequences:

```text
description = "Line one\nLine two"
shader_code = "shader_type canvas_item;\n\nvoid fragment() {\n    COLOR = vec4(1.0);\n}\n"
```

When serializing shader or multiline text, escape newlines and backslashes in
the actual file. Do not put literal unescaped line breaks inside an ordinary
quoted string unless the exact target syntax supports them.

## 12. Common resource patterns

### 12.1 Gradient

```text
[gd_resource type="Gradient" format=3]

[resource]
colors = PackedColorArray(1, 0, 0, 1, 0, 0, 1, 1)
offsets = PackedFloat32Array(0, 1)
```

`colors` and `offsets` are packed arrays. Their lengths and ordering must be
compatible with the `Gradient` resource.

### 12.2 Gradient texture with an internal gradient

```text
[gd_resource type="GradientTexture2D" format=3]

[sub_resource type="Gradient" id="Gradient_gradient"]
colors = PackedColorArray(1, 0, 0, 1, 0, 0, 1, 1)
offsets = PackedFloat32Array(0, 1)

[resource]
gradient = SubResource("Gradient_gradient")
width = 256
height = 256
fill_from = Vector2(0, 0)
fill_to = Vector2(1, 0)
```

Only include properties supported by the target `GradientTexture2D` version.
Default-valued dimensions and fill settings may be removed by Godot.

### 12.3 Standard material

```text
[gd_resource type="StandardMaterial3D" format=3]

[resource]
albedo_color = Color(0.2, 0.6, 1, 1)
metallic = 0.1
roughness = 0.45
```

Material properties are class-specific. A valid `StandardMaterial3D` property
cannot be assumed to exist on every `Material` subclass.

### 12.4 Shader material with an embedded shader

```text
[gd_resource type="ShaderMaterial" format=3]

[sub_resource type="Shader" id="Shader_shader"]
code = "shader_type canvas_item;\n\nvoid fragment() {\n    COLOR = texture(TEXTURE, UV);\n}\n"

[resource]
shader = SubResource("Shader_shader")
shader_parameter/brightness = 1.0
```

Shader parameter property names use the serialized
`shader_parameter/<uniform_name>` form. The uniform must exist in the shader
with a compatible type for the material parameter to be meaningful.

### 12.5 Shader material with an external shader

```text
[gd_resource type="ShaderMaterial" format=3]

[ext_resource type="Shader" path="res://shaders/water.gdshader" id="1_shader"]

[resource]
shader = ExtResource("1_shader")
shader_parameter/wave_strength = 0.25
```

Use an external shader when the shader is shared or maintained as its own
`.gdshader` file. Use an embedded `Shader` sub-resource when the shader is
intentionally private to the material.

### 12.6 Animation library

```text
[gd_resource type="AnimationLibrary" format=3]

[sub_resource type="Animation" id="Animation_idle"]
resource_name = "idle"
length = 1.0
loop_mode = 1
step = 0.05

[resource]
_data = {
"idle": SubResource("Animation_idle")
}
```

The `_data` dictionary maps animation names to `Animation` sub-resources.
Animation track serialization is complex and should follow the exact
Godot-generated structure described in the TSCN authoring guide.

### 12.7 Custom data resource

```text
[gd_resource type="Resource" format=3]

[ext_resource type="Script" path="res://data/item_data.gd" id="1_script"]
[ext_resource type="Script" path="res://data/stat_bonus.gd" id="2_script"]

[sub_resource type="Resource" id="Resource_bonus"]
script = ExtResource("2_script")
amount = 5

[resource]
script = ExtResource("1_script")
display_name = "Sword"
value = 100
bonus = SubResource("Resource_bonus")
```

The exact properties and script class must match the project. Do not use
generic names such as `display_name` or `value` unless the script declares
them.

## 13. Complex and generated resources

Some resources contain large packed arrays or dictionaries generated by the
editor/import pipeline:

- `ArrayMesh` surface data;
- `Image` and compressed image data;
- `TileSet` sources and atlas data;
- navigation polygons and meshes;
- imported animation and skeleton data;
- visual shader graphs;
- font and texture data;
- `MultiMesh` instance buffers.

These structures may include implementation-specific keys, packed byte
arrays, binary formats, indexes, and derived values. Do not fabricate them
from property names. The safest workflow is:

1. Create a minimal resource in Godot.
2. Configure the resource through the editor or a script.
3. Save it as `.tres`.
4. Inspect the generated text.
5. Change only the intended values while preserving the generated shape.

If the resource is generated from imported content, prefer changing the source
asset or import settings rather than hand-editing the generated `.tres`.

## 14. Resource sharing and local duplication

An external resource is normally shared:

```text
[ext_resource type="Material" path="res://materials/shared.tres" id="1_material"]

[resource]
material = ExtResource("1_material")
```

If multiple scene instances use the same resource, runtime changes to that
resource can be visible in all instances. This is often desirable for shared
materials, textures, and immutable data.

Set `resource_local_to_scene = true` when each `PackedScene` instance needs its
own duplicate:

```text
[gd_resource type="Resource" format=3]

[resource]
resource_local_to_scene = true
damage = 10
```

This flag takes effect when the resource is duplicated as part of
`PackedScene.instantiate()`. It does not convert an already loaded external
resource into separate copies retroactively.

Sub-resources are embedded in the parent resource and are normally local to
that parent file. Use external resources for data intended to be shared across
many files or edited independently.

## 15. Resource paths and loading

Scripts can load `.tres` files by filesystem path:

```gdscript
var item_data: Resource = load("res://data/item.tres")
var shared_material: Material = preload("res://materials/shared.tres")
```

They can also load by UID when the resource has a valid UID:

```gdscript
var item_data: Resource = load("uid://REPLACE_WITH_VALID_RESOURCE_UID")
```

`preload()` requires a constant path known while parsing the script.
`load()` resolves the path at runtime and can use a dynamic string. The result
must be checked or typed for the expected resource class.

Godot caches loaded resources by path. Loading the same resource path normally
returns the cached resource reference rather than a fresh independent copy.
Use `duplicate()` or `duplicate_deep()` in code when independent runtime data
is required.

## 16. Property and type accuracy

The `[gd_resource type="..."]` declaration does not make arbitrary properties
valid. The loader resolves each property against the resource class and its
script:

```text
[gd_resource type="Gradient" format=3]

[resource]
colors = PackedColorArray(1, 0, 0, 1, 0, 0, 1, 1)
```

Common failure causes:

- a property belongs to a different resource subclass;
- a property was renamed in the target Godot version;
- a float was supplied where an integer or packed array is required;
- an external resource's declared type does not match its file;
- a custom script no longer declares the serialized property;
- a resource reference uses a path instead of a local ID;
- a dictionary or array contains the wrong element types;
- an enum or bitmask uses the wrong integer values;
- a shader parameter name does not match a declared shader uniform;
- a generated resource's packed data has the wrong length or encoding.

When uncertain, inspect the class reference and a resource saved by the exact
target Godot version. The Inspector's display name is not necessarily the
serialized property name.

## 17. Canonical generation workflow

Use this workflow when generating a `.tres` file:

1. Identify the target Godot version, resource class, and project.
2. Decide whether the resource should be external/shared or embedded/local.
3. List every external resource and assign stable local IDs.
4. List every sub-resource and topologically sort its dependencies.
5. Choose a trustworthy resource UID or omit it.
6. Write the `[gd_resource]` header with the exact resource type.
7. Write external resource headings.
8. Write sub-resource headings and their properties.
9. Write one `[resource]` section for the main resource.
10. Serialize each property using the exact Variant type and generated shape.
11. Check custom script compatibility and exported property names.
12. Omit defaults and engine-managed metadata that cannot be generated reliably.
13. Verify every path, UID, local ID, type, property, and reference.
14. Parse and load the resource in the target Godot project when possible.

## 18. Validation checklist

The common project, type, ownership, identifier, dependency, lifetime, and
validation checklist in `shared_concepts.md` also applies.

### File structure

- The first heading is `[gd_resource ...]`.
- `format=3` is used for Godot 4.
- External resources appear before sub-resources.
- Referenced sub-resources appear before their users.
- There is one main `[resource]` section.
- No scene-only `[node]` or `[connection]` headings are present.
- New files do not add deprecated `load_steps`.

### Header and paths

- The declared resource `type` exists in the target engine/project.
- `script_class`, when present on target-generated output, matches the attached
  script and is preserved exactly.
- The header UID is valid, unique, and belongs to this resource, or is omitted.
- External paths use the intended `res://` location.
- External UIDs, when included, identify the paths they accompany.
- No filesystem path is passed to `ExtResource()` or `SubResource()`.

### IDs and references

- Every `ExtResource("id")` has one matching external heading.
- Every `SubResource("id")` has one matching sub-resource heading.
- IDs match exactly, including case.
- Sub-resource dependencies are ordered before their users.
- External and internal resource types are compatible with their properties.

### Properties and values

- Every property exists on the declared class or attached script.
- Every value has the correct Variant type.
- Packed arrays have the expected element type and length.
- Transforms, quaternions, colors, and vectors have the correct components.
- Arrays and dictionaries have valid delimiters and compatible contents.
- `NodePath`, `StringName`, and ordinary strings are not confused.
- Resource references use `ExtResource()` or `SubResource()`.
- Shader parameter names match shader uniforms.
- Defaults and engine-managed paths are not emitted unnecessarily.

### Custom resources

- The attached script extends `Resource` or a compatible subclass.
- The script path is valid and stable.
- Exported property names and types match the serialized file.
- Constructor parameters have defaults when Inspector creation is required.
- The resource does not depend on an unsupported inner script class.

### Runtime behavior

- Shared resources are intentionally shared.
- `resource_local_to_scene` is enabled when per-instance duplication is
  required.
- Mutable resources are duplicated in code when independent copies are needed.
- UID loads resolve to the intended resource.
- Complex generated data was copied from the target Godot version rather than
  fabricated.

## 19. Failure patterns to avoid

Do not:

- write JSON syntax instead of Godot Variant syntax;
- use `[gd_scene]` for a `.tres` resource;
- put the main resource properties under a made-up heading;
- use `ExtResource("res://file.tres")`;
- use `SubResource("res://file.tres")`;
- define a sub-resource after a sub-resource that references it;
- assume every `Resource` property exists on every subclass;
- serialize `resource_path` as if it were the resource's filesystem location;
- invent UIDs or copy example UIDs;
- assume an external resource is duplicated for each scene instance;
- use `resource_local_to_scene` after instantiation and expect existing copies
  to change;
- fabricate packed mesh, image, tile set, or imported data;
- use a custom script that does not extend `Resource`;
- serialize properties that no longer exist in the custom script;
- use an inner script class as a persistent resource type;
- use `...` as a literal placeholder in packed arrays;
- assume successful parsing proves successful resource loading.

## 20. Canonical template

Use this template as a starting point and replace every placeholder:

```text
[gd_resource type="Resource" format=3 uid="uid://REPLACE_WITH_VALID_UID"]

; External resources
[ext_resource type="Script" path="res://REPLACE_WITH_RESOURCE_SCRIPT.gd" id="1_script"]
[ext_resource type="Texture2D" path="res://REPLACE_WITH_TEXTURE.png" id="2_texture"]

; Internal resources. Dependencies must come first.
[sub_resource type="Gradient" id="Gradient_gradient"]
colors = PackedColorArray(1, 1, 1, 1, 0, 0, 0, 1)
offsets = PackedFloat32Array(0, 1)

; Main resource
[resource]
script = ExtResource("1_script")
texture = ExtResource("2_texture")
gradient = SubResource("Gradient_gradient")
resource_name = "REPLACE_WITH_RESOURCE_NAME"
```

Remove properties and resources not declared by the actual resource class or
script. Do not leave placeholder UIDs, paths, IDs, or property names in a real
file.

## 21. Source authority and limits

This guide describes the Godot text-resource container and common Resource
authoring patterns. It cannot define every property of every engine resource,
imported asset, plugin, or project script.

For any property not explicitly covered here:

1. Confirm the target resource class and inheritance chain.
2. Confirm the exact property name, default, and Variant type in the Godot 4.7
   class reference.
3. Inspect a resource saved by the target Godot version.
4. Preserve the generated value shape, ordering, packed data, and metadata.

The authoritative behavior is implemented by Godot's text resource loader and
the resource classes themselves. If this guide conflicts with output produced
by the target Godot version, prefer the target-version output and update the
guide with a minimal reproducible example.
